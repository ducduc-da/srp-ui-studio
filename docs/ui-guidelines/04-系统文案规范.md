# 04 系统文案规范

## 1. 语气

专业、直接、克制，像可靠的研究助手。说明事实和下一步，不夸大能力，不用“赋能、颠覆、重塑、智能化升级”等空泛表达。

## 2. 基本规则

- 标题优先使用名词或明确任务：`专题分析报告`、`资产中心`、`重命名对话`。
- 按钮使用动词：`开始分析`、`保存`、`重新生成`、`打开文件`。
- 同一动作全产品只保留一种叫法；不用“确定/确认/好的”混指保存。
- 中文与英文/数字之间保留空格；中文句末用全角标点。
- 标签、导航、按钮通常不加句号；完整说明句加句号。
- 时间使用紧凑表达：`刚刚`、`8 分钟前`、`2 小时前`、`昨天`、`8 月 28 日`。

## 3. 状态文案结构

- 加载：正在做什么，例如 `正在整理数据…`，不要只写 `Loading`。
- 空状态：现状 + 原因（可选）+ 下一步，例如 `还没有最终产物。完成一次分析后会显示在这里。`
- 成功：动作 + 结果，例如 `已保存到工作区`。
- 失败：发生了什么 + 可能原因 + 操作，例如 `生成失败，数据源暂时不可用。请稍后重试。`
- 权限：缺少什么 + 如何获得，例如 `你没有编辑权限，请联系空间管理员。`

## 4. 删除与高风险操作

- 标题点明对象：`删除“亚运舆情日报”？`
- 正文说明后果及可恢复性：`删除后将从最近对话中移除，且无法恢复。`
- 按钮使用明确动作：`取消` / `删除`，不使用 `是` / `否`。

## 5. 输入提示

Placeholder 只给示例或格式，不代替字段标题：

- 推荐：`例如：分析星冰乐 2025 年的产品口碑`
- 推荐：`搜索对话`
- 避免：`请输入内容`
- 避免：在 placeholder 中写长篇操作说明

## 6. AI 回答文案

- 先给结论，再给证据与方法；避免以“好的、当然可以”开头。
- 明确区分事实、推断和建议；虚构演示数据必须标记。
- 图表标题直接描述指标与范围，例如 `2025 年月度声量与互动趋势`。
- 思考折叠项只显示耗时，不把“趋势洞察/AI 助手”等身份条常驻在答案前。
