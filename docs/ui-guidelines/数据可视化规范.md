# SRP 数据可视化规范

适用于智能问数、自由探索、专题分析和报告产物中由 AI 生成的图表与表格。

## 1. 在回答中的层级

- AI 回答采用连续文档流，不给整段回答添加气泡、背景卡或头像条。
- 一个图表或一组关联图表可以拥有内部面板，用于界定数据区域；面板不等于回答气泡。
- 结论先于图表：先用 1–2 句话说明发现，再展示数据，图表下方补充口径、来源或限制。
- 图表与上一段正文间距 20–24px，与下一段正文间距 24–32px；同组图表间距 12–16px。

## 2. 图表容器

| 属性 | 规范 |
|---|---|
| 背景 | `bg.surface`；简单图表也可透明 |
| 边框 | 1px `border.default` |
| 圆角 | `radius.card`，即 11px |
| 内边距 | 桌面端 16–20px；窄屏 12–16px |
| 阴影 | 默认无阴影 |
| 单图高度 | 常规 260–320px；迷你趋势图 120–160px |

图表不能为了填满页面而任意拉高，也不能依靠横向滚动查看核心结论。必要时精简类别或切换为横向条形图。

## 3. 标题、说明与来源

- 图表眉题/指标类型：12px/18、500、`brand.primary` 或 `text.secondary`。
- 图表主标题：14–15px/22、600、`text.primary`。
- 副标题、单位、图例：11–12px/18、`text.secondary`。
- 坐标文字、数据来源、口径说明：11px/16、`text.tertiary`。
- 标题描述结论或指标范围，例如 `7 月促销形成全年声量峰值`，避免只写 `趋势图`。
- 来源统一放在图表底部：`数据来源：××；统计周期：2025.01–2025.12`。演示数据必须标注 `演示数据`。

## 4. 颜色系统

### 默认顺序

1. 青绿 `chart.teal`：主要系列或当前关注对象。
2. 黄 `chart.yellow`：第二比较系列或需要关注的波动。
3. 绿 `chart.green`：正向、增长、健康指标。
4. 玫红 `chart.rose`：负向类别；明确错误优先使用 `status.danger`。
5. 蓝 `chart.blue`、紫 `chart.purple`：更多离散类别。
6. 灰 `chart.neutral`：基准、其他、非重点系列。

- 同一页面相同指标始终使用同一颜色。
- 单指标图优先使用青绿单色阶，不为了“丰富”而多色。
- 离散类别建议不超过 6 色；超过时合并“其他”、分页或改用分面图。
- 渐变只可用于面积图的透明度衰减，不使用彩虹渐变或立体渐变。
- 正负对比使用绿/红并同步显示 `+`、`−`、箭头或文字标签。

## 5. 坐标轴、网格线与图例

- 网格线：1px `chart.grid`，只保留帮助读数的主网格线。
- 坐标轴文字：`chart.axis`；轴线可省略，保留时同样使用弱灰色。
- 数值轴原则上从 0 开始；若折线图为观察细微变化而截断坐标，必须明确标记。
- 图例靠近标题或图表上方，横向排列，系列色块 6–8px；不得漂浮在数据上遮挡内容。
- 系列少且空间允许时优先在线尾直接标注，减少视线往返。
- 关键数据可常驻标签，其余数据在 Tooltip 中显示，避免满图数字。

## 6. 图形类型

### 条形图

- 用于类别比较和排名；类别名称较长时使用横向条形图。
- 条宽 16–24px，条间距 8–12px；圆角不超过 3px，只处理条形末端。
- 从零基线开始，默认按数值排序；同一维度不得随意打乱顺序。
- 并列系列建议不超过 3 个；正负口碑对比可使用双向或并列条形。

### 折线图与面积图

- 用于连续时间趋势；主线 2.5px，次线 2px，可用虚线区分预测或对照。
- 默认不显示每个节点，只显示峰值、异常点或 hover 点。
- 面积填充使用主色 8%–20% 透明度，不遮挡网格与其他系列。
- 超过 4 条线时优先拆图或提供筛选。

### 饼图与环图

- 类别不超过 5 个，且总和必须具有明确的 100% 含义。
- 默认使用环图，内径约 56%–64%；中心可显示总量或最重要占比。
- 切片按占比排序，从 12 点方向开始；极小类别合并为“其他”。
- 类别比较优先考虑条形图，不能因为视觉丰富而使用饼图。

### KPI 指标

- 每组 2–4 个，数值为视觉重点；标签 12px，数值 26–32px，单位 11–12px。
- 增长率必须注明比较基准；避免只展示无上下文的大数字。

## 7. Tooltip 与交互

- Tooltip 使用深灰 `chart.tooltipBackground`、白字、8px 圆角和 8–10px 内边距。
- 内容顺序为：维度/时间、系列名、数值、单位；数值右对齐。
- hover 只高亮当前数据，不让其他图形完全消失；键盘 focus 应获得等价信息。
- 筛选、图例开关和时间范围变化后保持图表高度稳定，避免页面跳动。
- 加载使用图表区域骨架；空状态说明无数据原因；错误状态提供重试入口。

## 8. 表格视觉

| 元素 | 规范 |
|---|---|
| 表头 | 38–40px，高度；12–13px/600；`bg.subtle` |
| 数据行 | 40–44px；13–14px/20–22 |
| 分割线 | 1px `border.subtle`，不使用完整深色网格 |
| 表格外框 | 1px `border.default`，圆角 8–10px |
| 行 hover | `bg.subtle` |
| 选中行 | `bg.selected` + 明确选择控件 |

- 文本、日期左对齐；数字、金额、比例右对齐，并使用等宽数字特性 `font-variant-numeric: tabular-nums`。
- 列标题必须包含单位，或在表格说明中统一声明单位。
- 空值统一写 `—`；真正的数值 0 必须显示为 `0`，不能与空值混淆。
- 默认不使用斑马纹；超过 10 行且横向阅读困难时才可使用极弱斑马纹。
- 长文本最多两行省略，并通过 Tooltip、展开行或详情页查看完整内容。
- 首列可固定；横向滚动时必须保留滚动提示，关键结论列不可藏在最右侧。
- 排序列显示方向与排序优先级，不能只依赖颜色表达。

## 9. 数字格式

- 千位使用分隔符：`85,383`；百分比默认 1 位小数：`25.5%`。
- 大数字可以使用 `万/亿`，但同一图表保持统一单位，例如 `1,609 万`。
- 时间粒度统一，不混排 `1 月`、`2025-02` 和 `Mar`。
- 正增长显示 `+12.4%`，负增长显示 `−5.2%`；使用真正的负号或清晰短横。
- 小数位由分析精度决定，不展示数据本身不支持的虚假精度。

## 10. 响应式与可访问性

- 窄屏优先单列堆叠双图，图表高度保持至少 220px。
- 表格在窄屏可横向滚动或转换为键值列表，不缩小到无法阅读。
- 所有图表提供可访问标题与一句话摘要；核心数据应能以文字或表格读取。
- 不只依赖红绿区分；使用线型、纹理、标签或图标提供第二编码。
- 动画时长 180–300ms，并尊重 `prefers-reduced-motion`。

## 11. 禁止事项

- 禁止直接使用 ECharts、Recharts 等图表库默认主题。
- 禁止 3D 饼图、立体柱状图、仪表盘式装饰、彩虹渐变和高饱和背景。
- 禁止隐藏单位、数据来源、统计周期或必要的口径限制。
- 禁止把截图当作最终图表；图表应由结构化数据渲染并支持响应式。
- 禁止为了视觉填充添加与结论无关的图形。
