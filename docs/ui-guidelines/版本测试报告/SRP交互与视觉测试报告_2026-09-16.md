# SRP 交互与视觉测试报告

> 版本地址：`http://172.18.5.5:31578/`  
> 测试日期：2026-09-16  
> 测试重点：交互反馈、视觉层级、工作区、响应式观感、键盘与可访问性  
> 对照规范：`AGENTS.md`、`03-组件与交互规范.md`、`06-验收清单.md`、`数据可视化规范.md`

## 1. 结论摘要

当前版本的主流程已能连贯展示“登录 → 新建分析 → 模式切换 → 任务详情 → 工作区 → HTML 报告”，侧栏收起、任务筛选、数据源多选、工作区三类目、产物预览等基础能力可用。

但现阶段不建议直接作为视觉定稿。主要风险集中在四类：

1. **用户输入可能丢失**：带草稿切换分析模式时，内容直接被清空且无提示。
2. **任务详情阅读体验失衡**：长提示词原样展示 Markdown 符号，工作区关闭后文本行长失控。
3. **工作区大文件量场景不足**：873 个过程文件默认展开过多，缺少搜索、虚拟列表和按需加载。
4. **产物页未遵循现有视觉规范**：报告使用高饱和紫色、衬线字体及英文标题；在 600px 工作区中导航与表格拥挤，和 SRP 主产品割裂。

本轮记录：**P0 0 项、P1 8 项、P2 10 项、P3 2 项**。

## 3. P1 高优先级问题

### SRP-UI-001：切换分析模式会无提示清空未发送草稿

- **位置**：新建分析页，`智能问数 / 专题分析 / 自由探索` 标签切换。
- **复现**：在智能问数输入框输入文字但不发送 → 点击“专题分析” → 再切回“智能问数”。
- **实际**：原草稿被清空，没有确认、自动保存或恢复入口。
- **期望**：不同模式共享草稿，或分别保存草稿；若确实需要清空，必须先明确提示。
- **AI 定位建议**：搜索模式 Tabs 的 `onChange`、输入状态初始化、路由切换时的 state reset；不要在 Tab 切换时重新挂载整个 Composer。
- **验收**：输入 100 字后往返切换三种模式，草稿仍存在；刷新策略有明确产品定义。

### SRP-UI-002：长用户提示词未结构化，工作区开关会导致行长失控

- **位置**：任务详情页用户消息区。
- **实际**：长提示词把 `##`、`-`、反引号等 Markdown 语法作为普通文本展示，形成超长浅蓝气泡；关闭工作区后气泡扩展到接近整屏，阅读行长过长。
- **期望**：用户消息可保留浅色气泡，但正文最大宽度不超过内容区的 72%；长提示词默认显示摘要/前若干行并提供“展开全文”；Markdown 应按安全白名单渲染或去除语法符号。
- **AI 定位建议**：用户消息组件、Markdown renderer、`max-width`、工作区开关后的主栏布局计算。
- **验收**：工作区开关前后正文左边界不跳动；桌面端单行约 45–75 个中文字符；长内容可展开/收起。

### SRP-UI-003：过程文件树在大规模文件场景默认展开过多

- **位置**：工作区 → 过程文件；样本任务显示 873 个文件。
- **实际**：多个顶层目录及深层目录同时展开，DOM/可访问树包含大量节点；缺少搜索和筛选，定位文件成本高。
- **期望**：默认只展开首层或全部折叠；目录按需加载；超过 100 项使用虚拟列表；提供文件名搜索和类型筛选。
- **AI 定位建议**：ProcessFiles、FileTree、TreeNode、目录默认 `expandedKeys`、虚拟滚动配置。
- **验收**：873 文件首次打开时仅渲染可视节点；搜索 2 秒内返回；展开状态不导致面板明显卡顿。

### SRP-UI-004：HTML 报告与 SRP 主题不一致，窄工作区适配不足

- **位置**：工作区 → 最终产物 → `briefing.html`。
- **实际**：报告大量使用高饱和紫色、衬线字体、英文模块标题和大号渐变编号；600px 面板中顶部导航换行拥挤，宽表格阅读压力大。
- **期望**：生成报告必须消费 SRP 设计 token；默认使用产品字体、青绿主色和规定灰阶；窄面板自动切为单列、折叠目录或横向滚动表格。
- **AI 定位建议**：HTML 报告模板、生成提示词中的主题约束、artifact iframe 的宽度监听、报告 CSS breakpoint。
- **验收**：600px、800px、全屏三种宽度无导航碰撞；颜色、字体、图表、表格通过 `数据可视化规范.md`。

### SRP-UI-005：多处纯图标按钮缺少可访问名称

- **位置**：首页发送按钮、登录密码显隐、工作区标题栏三个图标按钮、工作区文件行末按钮。
- **实际**：部分按钮在可访问树中只有 `button` 或 `image eye`，没有名称；空输入时发送按钮甚至不进入可访问树。
- **期望**：所有纯图标操作使用语义化 `button`，提供 `aria-label` 和 Tooltip；禁用态仍可被辅助技术识别为禁用按钮。
- **AI 定位建议**：IconButton 公共组件；禁止业务页直接渲染裸图标作为点击目标。
- **验收**：仅查看可访问树即可理解所有按钮功能；键盘可聚焦，焦点态可见。

### SRP-UI-006：交付物下拉菜单无法用键盘选择

- **位置**：新建分析页 → “交付物”下拉。
- **实际**：菜单视觉上能打开，但“一页纸简报 / 长图文研报 / PPT / 数据看板”在可访问树中是普通文本；方向键与 Enter 无法选中。
- **期望**：使用统一 Select/Menu 组件，菜单项具有 `option` 或 `menuitemradio` 语义，支持上下键、Enter、Escape、Home/End。
- **AI 定位建议**：DeliverableSelect；核查是否用普通 `div` 模拟菜单。
- **验收**：不使用鼠标可完成打开、选择、关闭；关闭后焦点回到触发器。

### SRP-UI-007：任务行与搜索结果缺少可点击语义

- **位置**：左侧任务列表、任务搜索结果。
- **实际**：鼠标点击文字可进入任务，但多数行在可访问树中只是文本/容器，不是链接或按钮；键盘用户无法可靠进入。
- **期望**：任务标题使用链接，或整行使用可聚焦的语义化按钮；更多操作独立为按钮且不嵌套交互控件。
- **AI 定位建议**：TaskRow、SearchResultRow、RecentTaskItem；统一列表行交互骨架。
- **验收**：Tab 能逐项聚焦，Enter 打开任务，`…` 用独立 Tab 停靠点打开菜单；标题位置不因 hover/focus 改变。

### SRP-UI-008：嵌套下拉打开时按 Escape 会关闭整个弹窗

- **位置**：资产中心 → 新建 Prompt → 类型下拉。
- **复现**：打开“新建指令”弹窗 → 打开类型下拉 → 按 Escape。
- **实际**：整个“新建指令”弹窗被关闭，而不是只关闭下拉。
- **期望**：Escape 优先关闭最上层浮层；再次按 Escape 才关闭弹窗；焦点回到原触发器。
- **AI 定位建议**：Dialog 与 Select 的键盘事件冒泡、overlay stack、`stopPropagation`/统一弹层管理器。
- **验收**：按一次 Escape 只关闭下拉，表单内容保留；按第二次才关闭弹窗。

## 4. P2 中优先级问题

### SRP-UI-009：空输入发送无明确反馈

- **位置**：新建分析页输入框。
- **实际**：发送图标颜色较浅但状态不够明确；点击没有提示。
- **期望**：空输入时按钮明确禁用，并提供可访问的 disabled 状态；若允许点击，需提示“请输入分析问题”。

### SRP-UI-010：加载过程呈现为空白区或孤立转圈

- **位置**：打开已结束任务、打开 HTML 产物。
- **实际**：大面积空白中只有很小的加载指示，无法判断正在加载什么、是否失败。
- **期望**：任务正文、工作区和产物分别使用局部骨架；超过 3 秒显示说明，超过阈值提供重试。

### SRP-UI-011：资产中心空状态对比度过低且留白过大

- **位置**：资产中心列表。
- **实际**：空状态插图与文案接近背景色，主动作不突出，主体形成大面积无信息空白。
- **期望**：使用轻量图标 + 原因 + 下一步；正文至少使用 `text.secondary`，主操作使用品牌主按钮；不使用夸张插图。

### SRP-UI-012：新建指令正文输入框圆角过大

- **位置**：资产中心 → 新建指令弹窗。
- **实际**：多行文本框呈胶囊形，与普通输入、弹窗和卡片圆角不一致。
- **期望**：多行文本框使用 8–11px 圆角；弹窗 18px，内部控件不得继承弹窗圆角。

### SRP-UI-013：Prompt / 指令命名不一致

- **位置**：资产中心按钮“新建 Prompt”，弹窗标题“新建指令”。
- **期望**：统一使用一个用户可理解的名称；若产品术语确定为 Prompt，则标题、空状态、类型、成功反馈均一致。

### SRP-UI-014：任务搜索缺少明显退出方式

- **位置**：侧栏搜索分析。
- **实际**：Escape 会清空搜索词，但搜索模式仍保留；未发现明确关闭按钮。
- **期望**：输入框尾部提供清空/关闭；Escape 第一次清空，第二次退出搜索，或一次直接退出并恢复焦点。

### SRP-UI-015：自由探索缺少独立引导

- **位置**：新建分析页 → 自由探索。
- **实际**：输入占位文案与智能问数相同，仅交付物默认值变化，用户难理解模式差别。
- **期望**：用一句话说明适用场景，并提供与自由探索相符的示例问题或快捷建议。

### SRP-UI-016：登录错误只通过顶部 Toast 表达

- **位置**：登录页。
- **实际**：错误提示短暂出现在页面顶部，账号/密码字段未标记错误，Toast 的辅助技术语义不明确。
- **期望**：Toast 使用 `role=alert`；同时在表单内显示“账号或密码错误”，字段使用 `aria-invalid`，保留输入并将焦点放在密码框。

### SRP-UI-017：工作区右侧悬浮粉色按钮干扰产物阅读

- **位置**：任务详情页工作区右侧中部。
- **实际**：粉色圆形悬浮入口覆盖报告边缘，颜色和图标风格与 SRP 主骨架不一致。
- **期望**：若为必要能力，使用主题色、避开内容与滚动条并提供可收起机制；若非本页核心能力则移除。

### SRP-UI-018：工作区空状态和上传动作不够明显

- **位置**：工作区 → 我的上传。
- **实际**：空状态对比度较弱、空间过空；“上传文件”视觉入口不够明确。
- **期望**：明确说明支持格式、大小和上传后的用途；提供清晰的次按钮或主按钮，不只依赖图标。

## 5. P3 视觉打磨问题

### SRP-UI-019：登录页品牌标识重复

- 页头与登录卡片均出现 Logo/名称，视觉重心略显重复。保留一个主品牌区即可。

### SRP-UI-020：部分筛选和辅助状态层级偏弱

- 任务筛选已选状态、弱说明文字和部分空状态接近背景；建议按 token 复核 `text.secondary / text.tertiary / bg.selected`，不要通过过低透明度表达禁用或次要状态。

- 数说账号 / 本地账号切换可用；切换时账号保留、密码清空，安全性合理。
- 密码显隐功能本身可用，Enter 可提交登录。
- 数据源多选可用，选中后摘要会更新。
- 左侧侧栏收起与展开可用；收起后保留核心入口。
- 任务状态/类型筛选可用，筛选后的数量会更新。
- 工作区可关闭、重新打开，并支持拖拽改变宽度；本轮结束时已恢复 600px。
- 工作区类目已使用“最终产物 / 过程文件 / 我的上传”，且类目样式保持一致。

## 7. 建议修改顺序

### 第一批：先处理数据丢失、可操作性和大数据量场景

1. 修复模式切换草稿丢失。
2. 统一 IconButton、任务行、搜索结果和 Select/Menu 的语义与键盘操作。
3. 修复弹窗与下拉的 Escape 层级。
4. 重构过程文件树：默认折叠、搜索、虚拟列表、懒加载。

### 第二批：统一任务详情与报告视觉

1. 为长用户提示词增加摘要/展开和稳定最大宽度。
2. 建立 HTML 产物主题注入：字体、颜色、间距、表格、图表统一读取 token。
3. 为 600px/800px/全屏设置报告响应式断点。
4. 处理工作区加载、空状态和悬浮入口遮挡。

### 第三批：完成一致性打磨

1. 统一 Prompt/指令术语。
2. 优化资产中心空状态、新建指令输入框圆角和登录页重复品牌区。
3. 按 `06-验收清单.md` 完成 1440、1280、1024、768 四档复测。

## 8. 给研发 AI 的修改约束

执行修复前必须先读取同目录：

- `AGENTS.md`
- `tokens.json`
- `03-组件与交互规范.md`
- `数据可视化规范.md`
- `06-验收清单.md`

修改时遵守以下约束：

1. 优先修公共组件，不在单个页面重复补丁。
2. 不新增业务组件内硬编码色值、任意阴影或任意圆角。
3. 不因 hover、focus、selected、菜单出现而改变标题位置或内容区宽度。
4. 弹窗、菜单、Tooltip 统一使用公共 Overlay 管理和焦点恢复机制。
5. 生成 HTML 产物同样属于产品体验，必须使用数据可视化规范，不能视为不受约束的外部页面。
6. 每个问题修复后提交：修改组件、使用 token、键盘验证、响应式验证、未通过项。
